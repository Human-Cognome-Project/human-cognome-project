## Source identity and arithmetic

Each supplied calculation tree uses one prepared execution/source generation.
The existing weighted candidate binder validates full field/occurrence handles,
source row/generation/ordinal, exact count/denominator coverage, aliases and parent
coverage. The probe additionally rejects two expressed outputs owning the same
native field or diagnostic row. Only expressed nodes are supported; anonymous
same-comparison internal grouping remains outside this subset. It is a bounded
calculation tree, not a model-wide restriction on membership graphs.

Source body positions and physical masses are read from the current native f64
fixture and copied to a separate, charged, fixed snapshot before a poll. Both
BulkCopy and CpuDirect source paths are exercised. A leaf uses
`physical_mass * (f64(count) / f64(denominator))`, preserving source order and
including sleeping members. Parents combine published child XYZ and untrimmed
participating masses, without applying another share or recovering a discarded
first moment. Each destination applies its declared experimental Q once.
Internal aggregation introduces no distance factor; the fixture's declared
conceptual levels are independent of SNode depth/row order.

Initialization uses the existing candidate query to seed **both** slots with
complete current publications. Ordered initialization/reference queries are
explicit setup or frozen observations, never an ordinary per-poll solver.
Subsequent reductions use a first-input anchor and f64 sums. Independent host
references use long-double rational source weights and first moments; each
parent reference uses its children's published values. Fine f64 comparison
bounds cover conversion/reduction error. Quantized coordinates require the
correct cell exactly; no comparison bound selects activity or sleep.

## Publication and native work

The probe has one NativeSet for its numerical nodes, two preallocated four-word
slots and one i32 selector per row. These arrays are separate from the source
engine's flat field/reduction/history buffers. The source fixture's unchanged
activity is checked for preservation and does not schedule the probe.

An entered node consumes its bit before acquiring inputs. It acquires its own
and each child's selector with native SC atomic OR-zero, reads one complete
selected packet, calculates the result, then writes the entire inactive slot.
A changed XYZ **or mass** publishes through SC atomic XOR-one before native
parent notification. A mass-only change must propagate even with unchanged
coordinates. Duplicate activations collapse in the native bitmask.

Each row has one writer and at most one visit/publication per poll. Every reader
finishes before the next ordered poll may reuse a slot. No concurrent structural
writers, overlapping polls, lock/spin, second awake mask, queue, scheduling epoch
or per-depth ordinary solve is introduced. Newly activated peers may enter the
current native traversal or a following poll; record/worker order is not assumed.

Every acquired child packet is checked against the complete publication before
or after that poll, including the matching selector. The parent's result is
checked using the packets it actually acquired. Siblings need not represent one
simultaneous global snapshot. Own selector, at-most-one-visit, collision and
finite/positive-mass checks are independent diagnostics, not work selectors.
Bounded representative acquired-packet traces retain observed/before/after
XYZ/mass alongside root/reference outputs.

## Compiled access qualification

The actual arithmetic kernel's retained Program LLVM is inspected before the
launcher executable copy. The audit attributes ndarray bases through native
argument-buffer offsets and checks indirect-child data flow through the child
array argument. It verifies each required own acquire, every compiled child
acquire clone/epilogue and the publication exchange, rather than accepting an
aggregate atomic-count floor. Ordinary selector loads/stores, unknown external
pointer arguments, unattributed operations or missing/demoted required paths
fail qualification. Raw instructions and address-role mappings are retained.

The current module has one own acquire, three indirect-child acquire sites and
one publication site, all SC; selector argument 1's data pointer is at ABI offset
24, and indirect child indexes derive from argument 3. This qualifies these
compiled CPU kernels, not arbitrary specialization or CUDA memory ordering.
Any future production installation must qualify every actual reader/writer,
including force, repair, focus, geometry and inspection, with its own lifetime
and history contract.

## Matrix, rejection and limits

Four modes cross one/two native worker configurations with both source host paths.
Each checks actual CPU selection and exercises 18 layouts and 76 cases, including
the separate cancellation variant. Every case runs 32 reset/reuse rounds with
three input changes and alternating signs: **29,184 input transitions** overall.

Pairs cover both record orders, one word, adjacent/distant blocks and the final
valid row. Other fixtures cover two/three levels, fan-in, forward/reverse
five-node chains and a permuted 63-node binary tree. Unequal quarter weights,
thirds, repeated ordinals/source aliases, compatible overlap and independent
occurrences retain exact coverage. Explicit quarter-weight movements each
contribute `3h/4` to a Q_4 parent; together they cross its threshold. Separate
controls cancel complete opposing inputs before Q.

For every input, the limit is 16 ordinary polls, followed by eight polls with
correct reference values and no pending work or calculation. Quiet bits with
stale values fail. Later local/deep changes and mass-only perturbations repeat
without reset; raw work/poll/publication/notification counts and costs are kept.
Diagnostic clearing/inspection scans are measured test overhead and never select
calculation work. C2a's deliberately unsafe controls remain unchanged in the
full regression.

Ordered controls force child publication before/after parent consumption and
joint input availability before checking cumulative cancellation. Invalid output
aliasing, stale handles/rows, cycles, disconnected roots, incompatible coverage
and unsupported anonymous grouping leave the probe unbound and source state
unchanged. A committed source edit requires rebind/reinitialization. A source-only
inert tick also invalidates the held snapshot; the probe rejects before any
further native calculation. Existing generation/completed-tick observations
guard provenance, not scheduling. Fixture-only body perturbations run exclusively
between polls; no live body motion is coupled to stale hierarchy metadata.

## Resource accounting and reproduction

At N=P=70, H=140, R=512, probe arrays own 29,280 host and 29,280 native bytes,
plus 2,592 prepared binding bytes. The two publication slots/selector alone are
`68N` native bytes. Host before-poll/reference buffers add 7,000 bytes. Source
execution manifests, numerical shapes, source/graph fixture tables and fixed
object sizes are reported separately; neither source snapshots nor history are
free reuse of the old field buffer. Source fixtures are constructed during setup.

Each probe inspection reads 14,280 bytes. Configuration uploads 15,000 bytes;
snapshot uploads are 2,240 bytes, and both-slot initialization uploads 4,480 bytes.
Reset initialization also performs a probe inspection. Each case has 128 snapshots,
32 initializations and 153,440 bytes of candidate-query/inspection readback.
Source fixture inspections/updates are separate from probe inspection: per case,
448 source inspections read 18,048 bytes each in BulkCopy or 6,840 in CpuDirect;
128 fixture body uploads copy 6,160 bytes each only in BulkCopy. Source binding
and construction occur outside those ordinary case totals. Scalar/context metadata
and test-reference stack scratch are separate from these array transfer counts.

Setup, first binding/poll, initialization, ordinary kernel and inspection times
are separated from total case time. Known requested/list/pool/cursor/layout/
compiler counters must stay unchanged through first use, controls and all reuse.
Guarded native boundaries observe linked C++ new/new[] including workers, not
arbitrary malloc, page faults, residency or drivers. Fixed object/vector headers,
caller fixture construction temporaries, compiler/runtime storage, native pool
reservation and host reference stack space are separate. Host vectors are unpinned.
