## Concrete ownership issue and production trace

`LetterProjection` already owns the study UUID that supplies its occurrence namespace, but both `parents_` and `spare_parents_` retain a complete `ParentContribution` for each constructed edge. Every contribution owns another copy of that same study string. `parents()` exposes the retained active vector by const reference, coupling the public complete value to this private representation. The spare pool is private and has no public export accessor.

`project_letters` publishes active edges in source/parent order, with full occurrence key, `ParentValue` field object, ordinal and exact count. Selected projection copying explicitly selects the destination domain for every key, path and field object. `reserve_exposure` reserves both vectors for the complete edge inventory and constructs inactive contributions in the spare pool. `prepare_exposure` moves/reorders these same objects between pools without recreating their nested buffers. Committed/spare projection-pointer publication changes their roles while retaining the reserved objects. `projection_storage.cpp` counts both row capacities and all constructed nested backing.

The inventory found no production consumer of `parents()` outside this bookkeeping; tests use its full values to compare prepared native participation. Native mechanics consume prepared input definitions/occurrences and retain claim/incarnation/generation authority. The typed parent vectors are observation/publication metadata, not a second source of native state. This finding concerns study identity ownership only: source paths, complete field objects, ordered repeated edges/counts and recipe revision pins retain their current meaning.

## Context, public copies and work tradeoff

The test-only header/numeric witness takes the owning projection, pool selector and checked row index, then compares its existing header plus the retained full entry/path to a supplied complete key. It agrees with stored complete-key comparison for every observed row and has the same metered comparison work: 1,242 units for the fourteen-row fixture and 439 / 1,756 / 771 per one/four/three native view. Foreign study with identical numeric identity, changed full entry/path and malformed row index refuse. Zero/one-short work refuses, and exact-work retry succeeds with every allocation denied. This witness is not a production reader.

A separate stronger replay resolves each contribution's own occurrence/source against the pinned recipe, checks active/inactive role and compares field kind/object, ordinal and contribution count. It preserves repeated targets at distinct ordinals and shared language-byte definitions. The fourteen-row replay costs 9,204 units; it performs different duties from key comparison. It does not establish a requirement to scan source/recipe tables on every future frozen read.

Complete owning copies detach using the current row copy operation. The extended v1 fixture copies thirty-four active rows with 132 requests / 3,266 nested bytes, plus 7,072 caller-reserved row bytes. Its v2 reserved-pool control copies thirty-four active and twenty-four private inactive rows: 214 requests / 5,482 nested bytes, plus 12,064 row bytes. The latter includes test-only spare copies, not an existing public spare API. All individual copy allocation sites refuse, reclaim partial copies and retry with exact source/field/ordinal/count. Ordinary/selected copies and moves preserve values through original source/recipe/projection/domain death, including maximum entry, repeated/multibyte paths and character ordinal ten. Exported values retain no selected-domain allocator or weak domain lifetime.

## Bounded proposal requiring review

Use the projection's existing owned header for private parent study identity. Retain full numeric occurrence source, complete field object, ordinal and count in each private active/spare row. Replace the public vector-reference boundary with explicit active-parent count/index extraction that reconstructs complete independently owning `ParentContribution` values. Private frozen readers must receive the owning projection, pool and checked index; no raw detached numeric row acquires namespace. Preserve ordering and exact pool reuse through preparation refusal and publication. The public inactive pool remains private.

The observed redundant nested payload is the study-byte column above; the candidate ABI removes 48 bytes per row-capacity slot. Those are separate attribution surfaces, not implemented net savings. Actual replacement width, vector growth, copy/export requests, retained and whole-operation peak bytes, census/work charges and both-view publication behavior must be measured in a separately reviewed implementation. Existing header backing remains charged, and complete output copies still pay for their own study strings. Construction/immutable invariants should support checked contextual reads without promoting the stronger test replay into repeated frozen setup. No table, registry, new recipe lender, parent-target index, broader revision policy or mathematical change is proposed here.
