## Publication and borrowed metadata

The preparing `PreparedStudyOwner` retains its complete sealed `StructuralAdmissionPlan` through ordinary refusal/retry, native commit and every final full claim check. It additionally verifies that each committed native exact mass matches the original command. This fixed comparison is prepaid in metadata work, one additional unit per body. An unexpected mismatch uses the existing fail-closed publication path; no healthy partial owner is exposed.

After those checks and the existing pre-publication failure point, the owner swaps the plan's occurrence/definition and typed field vectors into its two empty domain-matched vectors. These constant-time swaps copy no keys and allocate nothing. The owner then destroys the consumed private plan, retiring commands, intrinsics, focus, hierarchy nodes/children/contributions, the plan header and duplicate source-stamp storage before marking its maps Published. Ordinary refusal leaves all replay data available. Failed postclaim publication remains unready, with no usable association loan.

The private `PreparedStudyOwner::plan` loan and `AssociationRows::plan` are removed. Published consumers use the existing stamped association view over the moved typed rows, full actual claims, pointer-free scales and pinned composed `ActiveAssembly`. The immutable row buffers keep their identity and complete nested pins. Their original command ordinals remain historical metadata; no published replay table or admission authority is exposed. Core reports and viewport owner tests migrate together.

`AssociationRows::body` obtains exact mass from the existing native `PreparedStorage::source_masses`, indexed by the actual body claim after the unchanged full context/incarnation/address/record and generation/tick checks. It does not use floating physical particle mass. Readiness also requires the consumed plan to be absent and durable row counts to match published claims. The source pin already owns the validated study/recipe identity, so report metadata uses that pin instead of duplicating the retired plan header.

Standalone `StructuralAdmissionPlan` handles retain their immutable outputs and borrowed `hierarchy()` lifetime. Only their existing exclusive preparing-owner friend can consume its own unloaned plan. This is a private owner contract change; public `ActiveSession` submission/tick/report semantics and native execution algorithms remain unchanged. No new registry, scheduler, comparison policy or numerical rule is introduced.
