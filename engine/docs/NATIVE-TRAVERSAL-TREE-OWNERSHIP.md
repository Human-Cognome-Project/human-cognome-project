## Owning handles and ordered teardown

[SNodeTreeOwner](../src/engine/snode_tree_owner.h) retains only the existing Program pointer and returned registered-tree handle. Program continues to own native descriptors/backing and performs retirement through `destroy_snode_tree`; the guard supplies the component's retirement obligation. It allocates no registry, allocator or backing and cannot be copied. The record-map owner uses the extracted guard in the same first-member position as its original private guard.

[Activity](../src/field/activity.h) declares the owner before every dependent member and a borrowed `Drain` phase guard after them. [NativeSelectionWorkspace](../src/field/native_selection.h) uses the same ordering and owns only its candidate-set tree. Committed sets still borrow Activity; [NativeSet](../src/field/native_set.h) remains a non-owning view.

Each constructor stores Program before registration and the returned tree pointer immediately on success. Both guards are fully initialized before the constructor body registers the tree. If later array/IR/kernel/context construction throws, ordinary C++ member unwind runs the final drain guard first, then destroys dependent members, then retires the tree through the first guard. Normal destruction follows that same ordering. The owner also synchronizes immediately before native retirement, preserving the existing record-map mechanism. These are Program-wide native barriers at teardown, with no added streaming allocation, scheduler or numerical protocol.

[Harness member order](../src/field/field.h) destroys placement/tick/hierarchy and numerical bindings before Activity. [TickExecution](../src/field/tick_execution.h) declares selection before its dependent kernel arrays, so those dependents die before the selection component. [CompiledKernel](../src/engine/runtime.h) destroys its bound context before its owned Kernel definition. Registered native trees therefore outlive these dependencies through normal teardown and constructor unwind, while Runtime/Program remain alive. Native registration's own failure handling is unchanged; the guard takes responsibility as soon as registration returns.

Compiler/JIT data retains its existing Program lifetime. Retiring a component tree neither purges the compilation cache nor makes an old bound kernel valid for a replacement tree. No other component's root is retired.
