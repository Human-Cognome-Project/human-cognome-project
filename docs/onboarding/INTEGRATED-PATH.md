## What the hot surface contains

The hot workbench is composed for a particular study. A shared definition can supply several live occurrences. The active owner binds those occurrences to the chosen exposure, fields and focus. Owner-scoped values can participate in supported logical operations. The prepared CPU route checks its narrower shared-input contract and refuses local overlays. A shared recipe, a logical assembly, a native execution handle and an exported snapshot each have a different lifetime. Use the [active workbench contract](../../engine/docs/ACTIVE-WORKBENCH.md) when crossing between them. Database, WAL and endpoint kernels remain peers serving the wider system.

## Three examples

1. **Change focus without building Taichi.** Run the [standalone value suite](FIRST-RUN.md#optional-check-logical-assembly-without-the-native-runtime). The [logical caller](../../engine/tests/active_assembly_test.cpp) binds repeated letter parts, clears focus, revises and restarts the assembly, and checks which focus the next binding sees. This is the shortest path for identity, provenance and scope work.
2. **Follow one retained native study.** The positive English-pair preset acquires the pinned recipe, chooses two aggregate occurrences and six explicit comparisons, publishes a prepared owner, ticks, reads back and releases the lease. The earlier refusal preset still demonstrates the missing caller decision for its own inputs. The [positive capture contract](../../engine/docs/RETAINED-POSITIVE-CAPTURE.md) and [hosted wrapper](../../engine/scripts/check_retained_positive_capture.sh) specify the fresh warm database and read-only source connections. The [stored viewer example](../../tools/viewport/examples/letter-study.json) is a separate capture for exploring the output format.
3. **Read a failed observation.** In the #417 moving case the original log located a leaf mismatch in round 28. The integrated [failure diagnostic](../../engine/docs/LEAF-FAILURE-DIAGNOSTICS.md) records tick, leaf, selectors, packet bits and ordered body inputs on future rejection. Its constructed Q6 example produces 29 versus 29.25. The operands of the original rejection remain unknown.

## Where qualification stops

The supported CPU ownership and independent build boundaries satisfy refactor Passes 1–3. Complete native live/peak accounting and admission credit, registered JIT retirement, general mixed-revision updates, GPU/concurrent qualification and a concrete Analyst remain separate work. Pass 4's structural-intent mathematics has its own [issue #324](https://github.com/Human-Cognome-Project/human-cognome-project/issues/324). See the [exit evidence](../../engine/docs/RESPONSIBILITY-MAP.md#refactor-exit-reconciliation--2026-11-23) before extending a claim beyond its fixture.
