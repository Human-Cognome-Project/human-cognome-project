# Choose your path

HCP onboarding is layered by the reader's purpose. Choose one path; the others remain available when your question or task crosses a boundary. Humans and agents use the same routes.

For an initial picture, think of Minecraft's composition from a relatively small set of building elements. HCP's intended model builds complexity through composition and records stable structures as reusable elements for further use. [Understand HCP](UNDERSTAND.md) connects that picture to definitions, live occurrences and fields.

## Reading paths

| I am here to… | Start here | Enough context to proceed |
|---|---|---|
| Work on an outstanding bounded task | [Work on a bounded task](AGENT-START.md) | You know the source, scope, applicable contracts and acceptance checks. |
| Understand what HCP is doing | [Understand HCP](UNDERSTAND.md) | You can explain the model and component roles; implementation chronology is optional. |
| Review a contribution | [Review a contribution](REVIEW.md) | You can compare its claims with the governing contract, diff and source-pinned evidence. |
| Build or inspect something locally | [First native check](FIRST-RUN.md) | The named smoke check runs, or you have identified the concrete setup blocker. |
| Learn how and why the project developed | [Follow the history](HISTORY.md) | You can trace a decision to its context, evidence and accepted successor. |
| Check what exists today | [Current state](CURRENT-STATE.md) | Built, provisional, held and remaining scope are distinguished. |

## How to follow a path

Read the entry page and its required task-specific references. Stop when its exit condition is met. A link to deeper explanation is available context, not an instruction to load the whole repository. If your work changes a boundary, follow that boundary's contract before proceeding.

Contributors read the short root [AGENTS](../../AGENTS.md), applicable component instructions and [work discipline](WORK-DISCIPLINE.md). [Covenant](../../covenant.md), [Charter](../../charter.md) and [contribution workflow](../../CONTRIBUTING.md) govern contributions. Readers exploring the project can follow conceptual or historical paths directly.

## Authority

Code and executable evidence establish what is built; explicitly accepted decisions govern required behavior. Report discrepancies. A research note, held proposal or old “next task” does not override an accepted contract. Current queue ownership lives in [current state](CURRENT-STATE.md) and the owning plan; evidence stays with its source pins.

[Documentation catalog](../documentation-map.md) locates deeper material. [Onboarding maintenance plan](ONBOARDING-PLAN.md) explains this structure and its acceptance checks.
