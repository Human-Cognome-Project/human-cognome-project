# Maintaining the onboarding routes

Readers choose a route in the [onboarding index](README.md). Keep each route short enough to reach its first useful action without reading project history.

| When something changes | Update |
|---|---|
| Assignment or acceptance | Record the decision on the owning issue. Update [current state](CURRENT-STATE.md) for a milestone change and the owning plan for implementation scope. |
| Runnable operator command or example | Update the [operator route](OPERATOR.md) and its component instructions. Verify the documented invocation and state its prerequisites. |
| Ownership, build dependency or data flow | Update the [source walkthrough](INTEGRATED-PATH.md) and the owning contract. |
| Build or evidence requirement | Update [first run](FIRST-RUN.md) or [validation](VALIDATION.md). |
| Superseded direction | Point the old entry to its successor and retain source-pinned evidence on the [history route](HISTORY.md). |

Check relative paths, fragments, entry anchors and command availability on the proposed tree. Keep one owner for each instruction. The [November migration plan](https://github.com/Human-Cognome-Project/human-cognome-project/blob/37110895741ba6b8523aa17cc0e692a06e1702e1/docs/onboarding/ONBOARDING-PLAN.md) preserves the original sequence.
