## Result and finite operation set

One prepared execution must accept structural letter/byte objects from the
configured stores, place newcomers through the engine, change its live
representation and focus, report coherently, and support controlled component
restart. Warm is the reusable toolbox; hot is the owner-controlled workbench;
Taichi holds current numerical state. Individual letters remain the test objects.

“All operations” for this handoff means the following explicit matrix. It does
not mean every deferred research feature in the issue tracker.

| Operation | Required result before GPU handoff |
|---|---|
| Prepare / empty ready | Independently bounded potential, payload, fields, relationships, activity, placement/contact work, identities, transport and report storage; warmed bindings; no physical objects. |
| First structural submission | No required world starts; reviewed empty-focus bootstrap; complete positive focal mass before populated readiness. |
| Tick | Existing force/contact/integration/determiner/type-phase rules with current data, sleeping contributors and local-coordinate precision; candidate movement and resulting contact coverage validate before publication. |
| Admit another occurrence | Engine-owned nearest-unoccupied placement at current focus, including sleepers and earlier arrivals; distinct occurrence state and full parent/membership bindings. |
| Refresh / structural edit | Changed counts, new/retired fields, memberships/shares and explicit contacts; only genuinely new/replaced physical rows initialize; survivors keep current state. |
| Remove / reuse | Explicit dependency removal, correct mass/focus/contact/activity effects, native recycling and stale-reference rejection. |
| Explicit aggregate/parts exchange | Atomically exchange already-supported letter/byte alternatives within prepared capacity; preserve unaffected occurrences and account for the replaced object's state under D7 below. |
| Explicit focus change / rebase | Validate requested focal fields, preserve physical arrangement and motion, repair dependent controls and wake requirements without full republication. |
| Report / capture | Exact source/owner/occurrence bindings and one completed execution snapshot, with capacity/present/awake counts and insertion observations. |
| Controlled restart | Reconstruct from structural data; optional validated owner restart positions remain separate; previous session handles fail. |
| Reject / fail / release | Ordinary failure leaves committed state healthy; post-mutation failure refuses current use; owned resources drain and release. |
| Exhaust prepared resources | Name the actual exhausted budget and retain current execution; expansion is a separate resource operation, not automatic admission. |

Automatic perspective selection, LoD slopes, arbitrary recomposition, analyst
reasoning, private DB acquisition, general checkpoint persistence, distributed
swarm machinery and held #123/#111 are outside this operation set. Explicit
supported representation changes do not select a perspective on the user's
behalf. Unsupported scale/layout families must be declared and rejected before
mutation; they cannot be silently counted as tested operations.

## Decision status

The settled rule is nearest unoccupied space to the current combined focal
centroid, with actual extents. These conventions complete the initialization and
lifecycle details left unapproved by #160. The #170 review accepts D1–D6 as
bounded here, including D6's exact-representability limit. Patrick confirmed D7
on 2026-10-23: “current position (or nearest) for expansion/compression,” with
nearest unoccupied to focus reserved for new placements.
The complete contract is accepted and releases the four implementation segments
without another routine permission step.

| ID | Convention |
|---|---|
| D1 — bootstrap | Require an explicit nonempty focal selection for populated operational admission. Validate its prospective structural membership first. Select the first exposed participant of the first selected field in canonical source occurrence order as the bootstrap anchor; place that participant at local zero. This explicitly establishes the first body, not merely a coordinate gauge. Place remaining bodies by the same nearest-free rule using the combined centroid of the already placed focal contributions; use the anchor until another focal contribution exists. All selected fields need positive mass before readiness. Empty prepared execution remains valid. No automatic focus selection or caller layout fallback. |
| D2 — ordinary batches | Freeze the validated focal point at batch entry, process newcomers in canonical occurrence/path order and update prospective occupancy after each placement. Recompute affected fields and final focal controls once for coherent publication. Bootstrap is the explicitly separate D1 case. This replaces #160's tentative per-arrival focus-update proposal. |
| D3 — new motion | Genuinely new bodies start with engine-owned zero velocity, zero force/displacement and motion flags, initial speed zero, and an awake bit. Existing fields then provide interaction through normal phases. No launch kick, all-coincident placeholder layout or survivor reset. |
| D4 — geometry / ties | Tangency is admissible. Validate stored coordinates against outward-rounded operative extents; use a documented coordinate/ULP-derived search certificate, never a fixed physical clearance. Resolve equally admissible minima deterministically in the operative frame, then source order. Genuine zero extents keep their existing geometric meaning; missing geometry must not be replaced with zero or a universal fixture radius. Cross-backend dynamic trajectories need mathematical coherence rather than bitwise equality. |
| D5 — restart | Structural restart is sufficient. Optional supplied positions are a separate owner-bound restart input, checked against definition revision, occurrence, exposure, units/frame and occupancy. Reject invalid hints before replacing a healthy execution; allow an explicit retry without hints. Starts stored in v1 recipes are never automatic hints. Position-only recovery uses D3 for initial motion; a full velocity/checkpoint format is not introduced implicitly. |
| D6 — focus / rebase | Only explicit supported focal-field requests change selection. Validate positive participating mass, then recompute the ordered combined centroid and its wake effects. A coordinate rebase is a separate engine operation: translate all present positions, published/previous centres and focal controls consistently, update the double reference, retain velocities, displacement vectors and weighted residue. Publish once; do not rebuild or reseed the study. Quantify f32 representability/error and reject unsupported transforms before mutation. |
| D7 — bounded exchange | Support explicit aggregate↔declared-byte-parts changes for existing letter occurrences, without automatic LoD selection. Preserve untouched physical records exactly. For the replaced logical occurrence, derive its current mass-weighted centre and linear velocity from outgoing execution state in the common operative frame. Transfer that velocity to replacement bodies. Their engine-owned placement targets the outgoing logical centre (the current position for an aggregate), using the nearest unoccupied position when extents/occupancy require it. Retire the old alternative only at coherent publication; never import recipe starts. Nearest-to-study-focus placement is reserved for genuinely new occurrences. |

D7 has a real contract boundary: changing the representation of an existing
logical object differs from adding a genuinely new occurrence. “Replacement”
here means the aggregate or constituent particles expressed by that **same
occurrence** after an explicit representation/LoD change: for the current tests,
one aggregate letter particle ↔ its declared byte particles. It does not mean a
newly submitted object or automatic LoD selection. Patrick's clarification
settles the distinction: use the outgoing logical centre as the exchange's
placement target, with extent-aware nearest-free placement for the expressed
bodies. Genuinely new occurrences target the current study focus. A representation
change does not itself move an existing object back toward that study focus.

Prospective occupancy excludes the outgoing mutually
exclusive alternative while retaining all unrelated occupants. Keep old-plus-new
native claim peaks from #169: same-batch retirement cannot fund claims. Reject an
exchange that does not fit, even when its final representation would fit.
Transfers must conserve exact source contribution accounting and supported
linear momentum within stated floating tolerances. This is bounded state mapping,
not a new force law or general recomposition system.

Using the old centre as a target does not guarantee that nonoverlapping replacement
bodies have exactly that combined centre. Record old centre, target, actual new
combined centre and initialization offset separately from subsequent motion.
The acceptance is unchanged external survivors, correct state/contribution
mapping and the reviewed placement objective; do not claim centre preservation
where geometry prevents it. A stronger centre-constrained packing contract would
need explicit review rather than an undocumented extra placement rule.

### Nearest-free search and proof obligation

For target F, new radius r and occupied centres/radii `(c_i,R_i)`, minimize
`|x-F|` subject to `|x-c_i| >= r+R_i`. Use F directly when admissible.
A first-free ray, fixed direction list or uniform candidate lattice cannot
establish the required nearest result for overlapping exclusions.

Proposed native implementation route:

1. Inspect existing Taichi C++ IR traversal, reductions and reservation facilities
   and use them for current-presence queries and bounded scratch. Do not add a
   particle scheduler or a competing allocator.
2. Obtain a valid free candidate/finite distance upper bound, then restrict the
   search to that target-centred bound. Boundary/intersection candidates can
   improve it; every candidate is checked against all relevant occupants.
3. Use conservative geometric bounds to refine unresolved regions until the
   best feasible stored point and the remaining distance lower bound differ by
   the reviewed coordinate/ULP-derived tolerance. An adaptive interval/box search
   is the proposed certificate route. Its boxes are numerical search workspace,
   not the model's particle lattice or placement sites. Handle contained,
   coincident, tangent and multi-sphere intersections, zero extents and degenerate
   directions explicitly. Derive error bounds for the actual arithmetic.
4. Use a prepared finite placement-work reservation. Report its visits, candidate
   tests and certificate bound. If work or numerical range is exhausted before
   certification, reject the whole operation before claims; do not return the
   best unchecked/uncertified point as a successful nearest result.
5. Check small cases against an independent C++ sphere-boundary/intersection
   reference and analytic cases. Include a case where individually nearest
   sphere projections are blocked and a multi-boundary solution is required.

The production search need not enumerate all triples for large P. Source review
must establish coverage and the certificate, not infer global minimality from
sampled examples. Describe worst-case work and measured supported profiles;
there is no unlimited-latency or universal convergence claim. Placement work is
calculation and may be substantial; logical native claim is still declaration.

## 3. Contact coverage and numerical publication

Occupancy and contact force coverage remain distinct. Keep the existing contact
law and pre-integration force semantics. Specify the union/deduplication of
explicit source pairs and engine-discovered physical pairs, with source metadata
preserved separately. Admission must reconcile relevant contacts/wakes even when
the supplied list is empty. Subsequent motion must not leave newly interacting
bodies permanently absent from coverage.

Prepare contact discovery/index/compaction storage and bindings. Prefer native
activity/presence traversal and reuse current geometry while hot: sleeping bodies
remain queryable occupants, while only motion/structural changes require ordinary
coverage updates. A bounded present-body scan is a correctness baseline where
native acceleration is unavailable; record its actual cost and do not scan V.
No custom loaded-array scheduler, hidden per-arrival allocation or silently
truncated pair list is acceptable.

Contact/work exhaustion is an ordinary **unchanged, healthy rejection**, including
when motion would create excess contacts. It therefore needs a candidate tick,
not overflow discovery after modifying committed positions. This transactional
path is new work; #169's existing live numerical tick does not supply it.

1. Under exclusive execution ownership, reconcile/preflight current contact
   coverage and prepare bounded transaction scratch from current backend state.
   Until publication, committed numerical arrays, activity bits, history,
   contacts/adjacency and execution bookkeeping remain unchanged. Do not first
   call a live activity reset/consume or clear live force/history buffers.
2. Evaluate the existing force, integration, determiner and dependent centroid/
   focal calculations into prepared candidate outputs. Contact forces read the
   pre-integration state and its validated coverage. Reuse the accepted numerical
   kernel logic; introduce no second solver. Derive transaction-local consume/
   wake effects through native type-phase activity/presence machinery, including
   ordinary invalidations. Keep one persistent native awake set per type; scratch
   intents are neither a second scheduler nor another population of particles.
   A sleeping peer cannot execute early because candidate propagation woke it.
3. Discover and compact prospective derived contacts against **candidate
   post-integration positions**, retaining sleeping occupants. Validate the
   explicit/derived union, both CSR directions, all pair/work/compaction limits
   and pending activity effects before any committed write. Preserve requested
   explicit pairs even when not penetrating; remove only derived coverage whose
   criterion no longer holds. Post-integration discoveries affect the following
   particle phase, not the force evaluation already staged for this tick.
4. Synchronize and inspect candidate completion/status. Only after all ordinary
   rejection checks pass, copy the affected candidate numerical/control outputs,
   install the complete contact/adjacency changes and apply the ordered native
   consume/wake effects. Publish the completed tick, frame and any topology/
   reference-generation changes together after completion. No report, source
   update or next tick may observe the intermediate copies.

On a named capacity/work rejection, discard scratch and return attempted demand
separately from the last completed report. Preserve committed positions, velocities,
forces, speed/motion state, displacement, centroid accumulators and residue/history,
focus/universal controls, native activity, contacts/adjacency, counts, parameter/
invalidation bookkeeping, frame and generation exactly; readiness stays true.
Do not download and restore a host snapshot or replay survivors to obtain this
guarantee. Scratch may be overwritten by the next attempt. Its P/G-sized numerical
storage and overlapping contact copies must be reserved and charged under §5;
ordinary batch scratch alone is insufficient for a tick touching all bodies.

An unexpected backend failure that makes candidate completion unreliable, or a
failure after committed copying begins, follows the explicit unready disposition.
It cannot be reported as an unchanged resource rejection. Expected contact/work
exhaustion must always be detected before that publication boundary. These rules
add a numerical transaction boundary, without changing the accepted force law,
integration order or particle/centroid phase predicates.

Extend #169's native commit, candidate reduction and wake machinery for generated
initialization, selection and exchange. Preserve survivor numerical/motion state,
untouched field history, fresh affected reductions, universal mass, ordered focal
arithmetic and mass/origin invalidation. Avoid adding pending residue twice.
Any new generated-contact ledger compaction invalidates affected row references
through a coherent committed generation. Reporting/frame counters are diagnostics,
not scheduling timestamps or additional awake states.
